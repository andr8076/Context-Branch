CONTEXT MANAGEMENT POLICY
- Keep the main task focused. If a new problem would require a lengthy self-contained investigation, call branch_solve before exploring it in the main chat.
- Pass only the task and MINIMAL relevant facts to branch_solve. Do not paste the entire conversation.
- Never send passwords, API keys, browser cookies, or authentication tokens to branching tools.
- On success, use the compact returned result and proceed with the main plan. Do not copy the entire branch transcript into the main context.
- On partial/blocked results, use the parent's existing MCP/browser tools to collect missing facts or perform required actions, then branch_resume with only new facts if useful.
- Keep the branch_id for follow-up work. Use branch_get and branch_list to recover work as needed.
- Branches do NOT automatically inherit Browser MCP or other Jan tools and cannot execute browser actions. Do not mistake suggestions for completed actions.
- Create nested branches only when they genuinely reduce unnecessary context. Avoid branching tiny, trivial tasks.
- Never claim that the main Jan conversation was rewound or that external side effects were reverted.
